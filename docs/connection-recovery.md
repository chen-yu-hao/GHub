# 0.1.7 连接恢复

本版处理客户端恢复逻辑和会话缓存边界，不改变远端 daemon 的生命周期，也不通过重新创建任务替代恢复会话。

会话缓存不再把完整长历史写成一条 SQLite 大行：只保留最近 64 个条目，并限制文本和 diff 大小，总记录控制在约 512 KB。读取旧缓存遇到 Android `CursorWindow` 超限时会删除该条缓存并从远端重新同步。

0.1.9 进一步将缓存拆成 `conversation_chunks` 分片表，每 16 个条目一行，并提供 Room 1→2 迁移。旧版单行缓存只在兼容读取时访问，成功写入分片后立即删除。

## 连接与网络

- 状态区分连接中、检查连接、等待网络、恢复连接、同步会话、已连接及需要处理。
- 默认网络可用/丢失、回到前台，以及请求超时会触发连接检查。使用已有稳定的 `thread/loaded/list` 只读请求，检查预算为 8 秒。服务端返回 RPC 错误也证明连接可达，不把它当成网络超时。
- 网络变化时先检查原连接；不会仅因 Android 网络回调直接关闭 SSH。相同主机同时只运行一个检查，有后续变化则合并为再检查一次。
- SSH 重建后完成初始化、列表同步、原会话 resume 和历史合并，才开放发送与审批。检查中仍可浏览、编辑草稿、切换项目；不会清空聊天或跳回首页。
- 已有连接检查成功、但会话同步被服务端拒绝时，保留 SSH 与独立终端/文件通道，显示同步错误。用户可选择其他会话或手动重试。
- 每次连接尝试有独立标识，运行实例也有独立 RPC epoch；先移除旧实例所有权，再异步关闭资源。旧实例事件和连接尝试的迟到回调不能改写新连接状态。

## 重试与后台

- 前台重试的基础间隔为 1、2、4、8、15、30 秒，加入约 ±20% 随机间隔并将实际等待上限限制为 30 秒，不再五次后停止。
- 没有默认网络时暂停连接尝试；默认网络恢复后立即安排一次。这里不强制要求公网验证，以允许仅访问局域网的 SSH 主机。
- 主机指纹拒绝、认证失败、未验证版本、明确的服务配置/协议拒绝停止自动重试。人工连接可重新尝试；用户主动断开会撤销恢复意图。
- 后台取消定时轮询、检查和等待重试，不主动关闭仍可用的连接；已经进行中的连接尝试可能完成。回到前台重新检查。没有增加前台服务，不承诺锁屏或后台长期保活。
- WebSocket 的 30 秒连接丢失检测参数、SSH 的 20 秒保活间隔保持原值。本版不通过单纯拉长超时掩盖失效连接。

## 流式事件与发送安全

- 协议响应直接唤醒请求，不等待 UI 消费通知。通知在独立 Default 调度器的有界队列中整理，再交给界面。
- 以约 75 毫秒窗口合并队尾连续的文字增量。只有方法以及除 delta 外所有参数完全相同、并有 thread/turn/item 标识时才能合并；不会跨审批、完成、错误或其他事件合并。
- 暂存队列最多 1024 项、按输入序列化长度累计最多 2,097,152 个字符；单次合并和批量取出另有限制，输出通道容量为 1。容量超限仍安全断开并重同步，明确记录 `event_backlog`，不静默丢弃事件或使用无界缓存。
- 历史合并前通过本地事件屏障等待此前通知处理完毕，再按已有轮次/消息身份合并，降低批处理积压导致重复追加文字的风险。屏障仅存在客户端内存中，不添加任何官方协议方法。
- 历史解析、会话缓存序列化移出主线程；后台轮询直接由监控协程执行，取消监控会取消其进行中的请求等待。
- 旧连接审批失效；同一连接已提交的审批不允许再次发送，服务端重复投递不会重置已提交状态。消息结果不确定仍保留待确认草稿，不自动重发或自动解锁。

## 提示与诊断

- 短暂恢复只显示紧凑状态提示；连续失败达到三次或无网络时提供立即重试。具体需要人工处理的错误保留明确提示。
- 诊断增加前后台、默认网络类型、连接尝试/协议 epoch、阶段、重试次数及检查结果。关闭原因区分 WebSocket 关闭码/来源/心跳、SSH、认证、指纹、超时、版本和事件积压。
- 不记录网络地址、凭据、服务端错误正文、关闭原因原文或聊天正文。诊断仍为进程内最近 200 条记录，由用户从设置导出；不上传遥测，也不保证进程退出后的网络日志保存。

## 交付边界

- 预览包：`dist/remote-gpt-0.1.9-preview.apk`，独立包名 `dev.remotegpt.preview`，调试签名。
- 本轮完成 Debug 编译；未添加或运行自动化测试，未进行真实手机 Wi-Fi/移动网络/VPN 切换、锁屏、大输出及多客户端审批回归。编译成功不等于这些场景已经通过。
- 普通 SSH shell 仍不保证断线存活；重新连接后可由用户恢复 tmux。手机断连不主动中断 daemon 中的 Codex 任务。

## 0.1.23：状态观察独立于当前页面

每个已连接主机分别运行两条同步循环。已订阅会话继续接收事件；状态观察通过只读 API 补齐未打开会话的结果，不恢复、重开或重发任务。

- 快速循环分页读取 `thread/loaded/list`，合并手机已记录为运行中的会话和当前会话。通过 `thread/turns/list(limit=1, itemsView=notLoaded)` 只取最新轮次状态，前台每轮完成后等待 3 秒；启用后台保持时等待 10 秒。实际延迟还包含请求耗时。
- 列表发现独立查询非归档最近会话，前台每轮等待 15 秒，后台保持时等待 30 秒。归档筛选、当前项目、文件/终端页面及当前服务器切换均不停止其他已连接主机的状态观察。
- 运行目标可来自全部 loaded 分页及已知运行记录，不局限于最近 40 条列表。列表分页本身仍按需加载；尚未发现、已经卸载的旧历史不承诺实时观察。
- 事件、连接恢复和回前台会唤醒观察循环。读取按主机和会话去重、最多三个并发；旧连接、期间发生的新状态事件或归档变更会使过期结果失效。
- 自动状态发现不替换归档视图、不重置已加载列表页，也不把新启动的非归档线程插入归档列表。消息正文仅按原有会话打开/分页流程获取；完成后的全文补同步仅针对当前选中会话。
- 关闭后台保持时，进入后台仍暂停定时观察；本次不改变 Android 的后台回收限制。

官方依据：https://developers.openai.com/codex/app-server/ 。0.165.0 schema 中省略轮次条目的值为 `notLoaded`，不是 `none`。

## 0.1.24：分级核对与减少重复写入

- 已订阅会话仍由事件即时更新。运行中和当前会话保持快速状态核对；其他 loaded 会话至少间隔 30 秒再查，每轮最多选取 8 个，新发现的 loaded 会话优先，其余优先检查最久未检查的目标。大量空闲会话的核对延迟还包含排队与网络耗时，不承诺所有会话 3 秒内更新。
- 未成功读取到有效轮次的会话在前三次失败后各等待 3 秒重试，随后退回 30 秒，避免创建时历史尚未落盘造成长时间漏观察，同时限制永久空会话的查询负担。
- 最近会话列表仍独立按 15 秒 / 30 秒发现变化。新增或摘要变化的会话立即进入状态核对；未打开、已归档视图下和其他服务器的状态观察不依赖进入聊天页。
- 没有变化的结果直接保留当前状态；最近会话摘要只在变化时写入 Room，项目列表只在变化时写入 DataStore。未知或不改变正文的通知不再触发正文缓存写入。
- 打开会话不再先等待保存当前位置；本地缓存解码在后台执行。缓存按序列化数据分块，保留最近 64 个条目内完整的用户/助手正文，避免将长 Markdown 从中间截断。工具输出与 diff 仍有缓存长度限制。兼容旧缓存格式；已被旧版本截断的正文由远端历史补全。
- 这仍是 SSH 长连接、订阅事件与只读核对的组合，没有新增全局推送服务，也未改变系统后台存活限制。

## 开发测试环境隔离

`scripts/ssh_fixture.py` 同时管理独立 SSH 服务与独立 Codex daemon；Android、JVM、Python 测试必须使用返回的 `fixture["codex"]` 包装器。`scripts/probe.py --exercise` 默认自动建立独立环境；使用 `--ssh-config` 时必须传入同一个 fixture 包装器。只读 probe 仍可观察现有环境。

依据：官方配置文档说明 Codex 本地状态位于 `CODEX_HOME`：https://developers.openai.com/codex/config-advanced/#config-and-state-locations 。独立环境仅设置子进程的该目录，不更改用户的配置或系统服务；退出仅执行该独立 daemon 的 stop，不调用日常环境的 restart/stop/bootstrap。

## 0.1.27：优先恢复当前会话与复用订阅

本节替代前文旧版本中“账号、模型、列表和历史全部同步后才在线”以及“全局三个状态读取名额”的描述。

- SSH、proxy 和 initialize 完成后标记连接在线，先发起当前会话恢复。账号、模型和最近会话发现分别异步进行，其失败不会让健康连接下线。当前会话尚未恢复时通过 `loadingHistory` 阻止发送；审批仍必须属于当前 RPC epoch。没有重放发送或审批。
- `SessionSync` 只存在于单条连接内。第一次打开必须订阅并读历史，同连接重新打开已同步会话复用订阅和内存内容。重建连接后不沿用订阅标记；收到关闭、卸载、归档事件也会使订阅失效。空会话的只读 fallback 不算成功订阅，手机新建会话则利用 `thread/start` 已建立的订阅。
- 完成事件、状态检查发现变化、清除缓存和手动同步会将历史标为待校验；同一会话的历史请求按序执行，并合并重复校验。请求期间又收到完成事件，不会把未校验的版本标为最新。旧历史分页不会清除最新历史的待校验标记。
- 仍使用现有 `thread/turns/list` 最近 20 轮接口修复历史；本版减少重复请求，没有增加官方协议不提供的增量游标。回前台先检测连接，正在运行的当前会话补校验正文，稳定完成会话依靠有效订阅和状态检查。检查期间健康连接不再反复切换到全局“检查中/同步中”。
- 每个主机独立保留当前会话 1 个、其他运行会话 2 个、空闲会话 2 个状态读取名额。当前会话、其他运行会话、loaded 发现/空闲检查、最近列表各有独立循环；慢 loaded 请求或空闲批次不会阻塞下一轮当前会话检查。状态事件唤醒当前与运行会话循环。
- 已订阅会话继续使用实时事件。未订阅会话仍需兜底检查：当前/运行会话前台每轮后约 3 秒、后台保持约 10 秒，最近列表 15/30 秒，空闲 loaded 会话至少约 30 秒且每批最多 8 个。这些不是端到端延迟上限；不承诺全局实时推送。
- 导出的诊断增加进程内聚合耗时：RPC 方法的成功/失败请求耗时、事件接收到消费的排队耗时、状态应用耗时、状态到 Compose 提交、缓存读取/打开就绪、历史读取和状态请求排队。仅含本地操作名称、次数、平均值和最大值，无消息正文、参数、路径或主机地址。Compose 提交不是屏幕实际呈现或 Markdown 解析完成时间，也不是帧率指标；未及时显示页面时还可能包含页面不可见期间的等待，不可直接当作前台渲染延迟。

官方协议说明：https://developers.openai.com/codex/app-server/ 。订阅复用不等于订阅所有会话；本版没有为加速发现而批量 resume 未打开会话。
