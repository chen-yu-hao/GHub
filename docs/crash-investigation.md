# 0.1.4：重复列表 key 崩溃修正

## 用户日志与确认依据

用户提供的诊断来自 Remote GPT 0.1.3、Android API 36。异常为 `IllegalArgumentException`，调用链从 `InlineClassHelperKt.throwIllegalArgumentException` 经 `LayoutNodeSubcompositionsState.subcompose:1366` 进入 `LazyListMeasureKt.measureLazyList`。

核对当前实际依赖 Compose UI 1.9.4 的源码和发布 AAR 字节码行号表：`subcompose` 的 1366 行对应 `Key ... was already used` 异常，即同一次列表布局使用了重复 key。源码位于 `SubcomposeLayout.kt` 597–599 行；内联后的行号与用户堆栈一致。这确认了异常类别，但原日志没有保存 key 或页面，不能确认具体哪条记录、哪个列表触发。

## 修正范围

- 聊天记录以轮次 ID 和消息 ID 共同标识，使用长度前缀编码避免分隔符碰撞。历史分页、流式事件、消息替换和 UI key 均使用同一标识。
- 历史页与旧缓存按复合标识整理重复项，保留第一次出现的位置；重复项中的完成态不会被未完成态覆盖，不同轮次的同名消息保留为两条。
- 聊天加载、空态、运行中提示与消息使用不同 key 前缀；最近会话也与首页重点卡片隔离命名空间。
- 首次及分页会话列表按会话 ID 去重，模型选项按实际发送的模型标识去重，旧草稿附件按附件 ID 去重。
- 旧缓存读取时自动整理，未改变数据库结构。若旧版曾错误合并了不同轮次的同名消息，已丢失的内容需要重新读取远端历史，不能从本地残缺记录推断恢复。
- 诊断增加固定枚举页面名称，以及严格匹配已知 Compose 重复 key 异常后的固定类别标签。异常正文和具体 key 仍不会保存，避免泄露路径或用户数据。

## 交付与验证边界

`dist/remote-gpt-0.1.4-preview.apk`，独立预览包名 `dev.remotegpt.preview`，版本号 5，沿用调试签名。

已完成对应框架源码/字节码核对、合并与 key 生成路径的代码检查，以及 `:app:assembleDebug` 编译。未新增或运行自动化测试，未在用户 API 36 真机复现和回归。已修正查到的重复标识风险，不能据此承诺所有连接、聊天和切页闪退均已消除。

# 0.1.1 历史排查记录

用户报告触发场景：连接、聊天或切换页面。尚无真机型号、Android 版本及对应崩溃堆栈。

## 已观察到的证据

- 在本地 API 35 模拟器的独立预览包中，冷启动、连接到明确不可用的本机端口、打开离线缓存聊天、切换文件页面未复现闪退。
- 已有 API 29 旧 instrumentation 日志含 Compose SlotWriter 在销毁 Activity 时的数组越界。它来自早期设备流程，不能直接认定是这次用户遇到的原因。
- 没有修改用户服务器，也没有清理用户设备数据。离线会话与不可用主机均为本地模拟器专用复现数据。

## 本次处理

- 将打开会话时的偏好写入、缓存读取纳入已有错误边界；本地持久化任务处理 I/O、数据库和密钥存储异常，协程取消继续传播。
- 诊断导出对空输出流与写入失败给出错误，避免在主线程协程上产生未处理异常。
- 系统栏配置只在主题改变时执行，避免每次流式消息重组都重复修改窗口配置。
- 设置、主机管理和配置改为页面；主机保存按实际结果返回，失败不关闭表单。
- 安装本地崩溃记录处理器，保存最多 24 KB 的异常类型、调用栈、应用版本、API 等信息，不保存异常消息、线程名、密钥、路径参数或对话内容。不吞掉异常，仍交由 Android 正常处理进程退出。
- 通过“设置 → 导出诊断记录”主动导出最近一次崩溃；无自动上传。

## 当前结论与交付

已完成 Debug 构建和模拟器页面查看；本轮未新增或运行自动化测试，也未验证真实 SSH / daemon、真机网络切换或全部崩溃场景。上述错误边界属于已发现代码风险的修复，不等于确认并修复了用户报告的闪退根因。

预览包 `dist/remote-gpt-0.1.1-preview.apk` 使用独立包名 `dev.remotegpt.preview`，桌面显示“Remote GPT 预览”。如再次闪退，重开该版本，进入设置导出诊断记录，以便定位实际调用栈。
