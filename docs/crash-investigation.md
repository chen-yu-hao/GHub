# 崩溃诊断与列表标识

## 收集诊断

遇到闪退后，重新打开 GHub，在「设置 → 导出诊断记录」中导出日志。反馈时附上应用版本、Android 版本、设备型号和触发步骤，便于将调用栈与具体页面对应。

崩溃记录保存异常类型、调用栈、应用与系统版本，大小上限为 24 KB。诊断使用固定页面名称和错误类别，省略异常消息、凭据和聊天正文。记录导出后可由用户附到 Issue。

## 案例：0.1.4 的重复列表 key

0.1.3 的一份 API 36 日志显示 `IllegalArgumentException`，调用链经过 `LayoutNodeSubcompositionsState.subcompose` 和 `LazyListMeasureKt.measureLazyList`。对照 Compose UI 1.9.4 的源码及 AAR 行号表，对应异常为 `Key ... was already used`。

原日志没有具体 key 和页面信息，因此修正覆盖了各列表的标识与合并路径：

- 聊天条目使用 turn ID 与 item ID 的复合标识，通过长度前缀编码区分字段。
- 历史页、缓存与流式事件共用同一标识；重复条目保留原位置，完成态优先。
- 加载提示、空态、消息和其他列表元素使用独立 key 前缀。
- 会话按会话 ID 去重，模型按模型标识去重，草稿附件按附件 ID 去重。

旧缓存读取时整理重复项，并由远端历史补齐内容。诊断中增加重复 key 的固定错误类别，便于后续定位。

## 维护要点

修改分页、缓存合并或列表结构时，检查相同 item ID 出现在不同 turn、历史与增量重复到达、最终条目替换增量等情况。UI key 应与数据层身份一致。

持久化和诊断导出在明确的错误边界内处理 I/O、数据库与密钥存储异常，协程取消继续向上传播。设备回归方法见[测试指南](verification.md)。
